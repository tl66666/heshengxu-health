# 微信认证与个人网站视觉重构设计

## 目标

修复和生序微信小程序发布版本的认证入口与首次建档流程，同时保持 App 邮箱密码认证独立；重构个人网站实习经历、竞赛荣誉、岗位能力三个区域，解决背景发黑、透明蒙层发灰、文字不清晰和背景素材未完整铺满的问题。

## 认证边界

- 微信小程序使用 `uni.login({ provider: 'weixin' })` 获取临时 code，由服务端 `/auth/wechat/login` 换取 openid 对应的和生序用户与访问令牌。
- App 只使用 `/auth/app/register`、`/auth/app/login` 和邮箱密码，不跳转微信授权页。
- 两端共用服务端 User、Session、健康档案和 userId 数据隔离规则，但不共用登录界面或身份提供方。
- 小程序首次启动路径固定为：品牌加载页 -> 微信授权确认页 -> 服务端登录成功 -> 无档案进入建档 -> 有档案进入首页。
- App 首次启动路径固定为：品牌加载页 -> 注册/登录页 -> 无档案进入建档 -> 有档案进入首页。
- 小程序授权失败时停留在授权页，显示可理解的网络/配置提示和重试按钮，不进入 App 登录页，也不读取游客档案绕过认证。

## 小程序页面设计

新增微信授权专属页面。页面使用和生序现有明亮奶油白与清透绿色视觉，展示序序形象、授权用途和主按钮“微信授权登录”。不索取手机号；微信基础登录不依赖头像昵称授权。按钮触发微信 code 登录，完成后回到 Bootstrap，由 Bootstrap 在已认证状态下检查健康档案。

Bootstrap 只负责编排，不弹循环重试 Modal。小程序未登录跳授权页，App 未登录跳 AppAuthPage，认证完成后统一检查本地/远程档案。路由判断必须在读取本地健康档案前完成。

## 发布与错误处理

- 服务端微信配置缺失、AppID/AppSecret 不匹配、code 过期分别映射为可读错误。
- 构建时校验 AppAuthPage 不会成为 mp-weixin 的入口，微信授权页不会成为 App 的入口。
- 微信开发者工具导入正式构建目录 `apps/mini/dist/build/mp-weixin`。
- 验证构建体积、API 域名、授权接口路径和页面路由。

## 个人网站视觉方向

- 实习经历：使用有层次的明亮青绿色数字工作流背景，保留足够留白，正文落在高对比实色内容区，不使用全黑底或低透明玻璃卡。
- 竞赛荣誉：使用清透蓝紫纸张/舞台光背景，证书图片完整展示，文字区使用浅色实底；TRAE 文案固定为“从 3.7 万余名参赛选手中获得年度 350 强”。
- 岗位能力：保留图 4 对应的云层动态背景原始亮度与完整铺满，取消覆盖全区的灰黑透明层；标题和五类岗位放入局部深色实底区域，确保对比度。
- 和生序项目：两张真实运行截图沿用城会玩式直接呈现，不增加边框、黑色底板或阴影框，保持完整比例。

## 验收

- 自动测试覆盖小程序/App 路由隔离、微信登录失败状态和“认证后才检查档案”。
- mini 单测、类型检查、mp-weixin 生产构建通过。
- 页面静态检查确认三个视觉区块背景不再为纯黑，文字颜色达到稳定高对比，和生序截图无边框/黑底。
- 两个仓库只提交任务相关文件，不包含密钥、构建缓存或既有无关改动。
