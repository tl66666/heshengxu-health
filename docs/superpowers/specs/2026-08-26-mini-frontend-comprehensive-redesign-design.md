# 和生序小程序前端全面重构设计

**日期：** 2026-08-26  
**范围：** 微信小程序前端视觉、交互、导航、状态与资源规范  
**目标：** 在保留 uni-app + Vue 3 技术栈和已有业务逻辑的前提下，建立一套统一、可验证、适合健康管理高频使用的移动端界面。

## 1. 现状审计结论

### 1.1 截图中的直接问题

- 建档欢迎页原先使用横屏 `assets/illustrations/hero.jpg`，用户已确认将其保留给网页端项目展示；小程序建档页改用竖屏 `assets/illustrations/onboarding-hero-vertical.png`，重点修复图片与导航、文字和按钮之间的版式关系。
- 页面内 `AppNavBar` 与微信开发者工具顶部系统导航不是同一个层级。系统导航不由页面控制，页面只能控制其下方的应用导航；当前大图负边距和应用导航高度组合后，造成标题、返回、退出和图片视觉挤压。
- 返回按钮和退出按钮之前使用微信原生 `<icon>`，平台渲染风格不可控，和页面 SVG 图标体系不一致。
- 欢迎页同时出现顶部标题、应用标题、序序介绍、品牌名、主标题、说明和按钮，首屏主任务不够集中。
- 页面操作按钮的状态缺少统一规则：正常、按下、禁用、保存中、网络失败、重新进入没有统一呈现。

### 1.2 全局结构问题

- 业务页各自维护页面内边距、标题层级、卡片边框和按钮样式，导致首页、记录、计划、我的看起来不像同一个产品。
- `MiniTabBar`、`AppNavBar`、`IllustratedHero`、`XuxuChatComposer` 没有共享同一套尺寸、颜色、图标和安全区规则。
- 页面内容没有明确区分“开放列表”“单一主卡片”“表单面板”“沉浸式聊天工作区”，多个页面重复使用厚重卡片。
- API、微信本地演示兜底和未来云开发适配没有在界面状态上明确区分，导致跳转成功但数据为空、或错误提示阻断主流程。

### 1.3 资源问题

- `assets/illustrations/` 已有治愈系场景插画和序序素材，`hero.jpg` 只作为网页端展示素材；小程序建档使用竖屏序序主视觉，其他页面按场景选择素材，不重复堆叠。
- 图标目前只有首页、记录、计划、我的、前进方向等基础 SVG；返回、关闭、完成状态已补充 SVG，但仍需建立完整图标清单和命名规范。
- 页面不允许使用 emoji、Unicode 符号、微信原生系统 icon 或 CSS 手绘图形替代正式图标。

## 2. 设计方向

### 2.1 视觉定位

采用“轻杂志式健康日志”作为小程序统一视觉：

- 背景：浅雾绿与米白，避免大面积深绿和高饱和渐变。
- 内容：开放留白、细分隔线、少量真正有意义的浅色区域。
- 重点：每个页面只突出一个主要任务，次要入口以列表行或文字操作承载。
- 插画：只出现在主视觉、空状态、完成反馈和序序陪伴场景，不用插画填满每张卡片。
- 文字：标题短、说明短、按钮明确，避免重复解释同一件事。

### 2.2 统一设计令牌

令牌只保留一套，放在小程序共享样式层，页面不再各自发明近似颜色。

| 类别 | 规则 |
| --- | --- |
| 页面背景 | `#F7FBF8` |
| 浅色区域 | `#EEF6EF`、`#FFFDF5` |
| 主文字 | `#214632` |
| 次文字 | `#71897A` |
| 主色 | `#347C50` |
| 主色浅底 | `#E8F4E8` |
| 边界 | `#DCEADD`、`#E4EEE5` |
| 警示 | `#B85E43` / `#FFF1ED` |
| 圆角 | 小控件 10-14rpx，内容区域 16-20rpx，禁止无意义超大圆角 |
| 间距 | 8、12、16、20、24、32、40rpx 基础节奏 |
| 底部安全区 | 所有 Tab 页内容底部至少预留 `220rpx` |

### 2.3 图标规范

- 来源优先级：正式 SVG 资源 > 已验证的图标库；禁止 `<icon>`、emoji、字符箭头和 CSS 绘图。
- 文件命名使用小写短横线：`home.svg`、`journal.svg`、`back.svg`、`close.svg`、`check.svg`。
- 图标统一 `24 x 24` viewBox，线宽 1.8-2，使用 `currentColor` 或明确的设计令牌颜色。
- 导航图标 38-44rpx；行内图标 32-38rpx；按钮图标 30-34rpx。
- 图标必须有明确语义，不能为了装饰重复出现。

## 3. 页面与交互蓝图

### 3.1 Bootstrap 启动页

**任务：** 让首次用户理解产品并进入建档，不承担业务信息展示。

**结构：** 卡通序序主视觉、品牌名、一个短标题、一句说明、一个主按钮。网络检测只作为内部状态，不在首屏显示技术错误。

**规则：** 已有本地档案直接进入首页；无档案进入建档；请求失败不能阻断本地建档。

### 3.2 Onboarding 建档页

**任务：** 用最少步骤收集可生成健康管理建议的基础信息。

**步骤：** 欢迎 → 称呼与性别 → 身高体重与实时 BMI → 健康方向 → 确认保存。

**统一页面壳：** 顶部应用导航只保留返回和退出，应用标题居中；步骤内容从导航下方开始，不使用负边距覆盖导航；底部操作区固定在内容流末尾并避开安全区。

**BMI 规则：** 输入或滑块变化立即更新数值、标签、建议和刻度；缺少任一输入时显示空状态；BMI 仅作为健康管理参考，不使用医疗诊断语气。

**按钮规则：** 返回为透明文字按钮 + SVG；退出为低强调文字按钮 + SVG；主按钮使用单一绿色实心样式；保存中显示 loading 并禁用重复提交；网络不可用时保存本地并进入首页。

**资源规则：** 小程序欢迎页使用 `onboarding-hero-vertical.png`；图片作为完整主视觉背景，文字通过独立内容层叠加，禁止裁切到标题、按钮或导航区域。`hero.jpg` 只用于网页端展示。其他页面继续使用现有卡通序序和健康场景插画。

### 3.3 Home 首页

**任务：** 回答“今天最重要的一件事”。

**结构：** 顶部问候与日期 → 一张主视觉 → 一个主行动 → 序序聊天入口 → 今日小行动列表 → 记录和计划摘要 → 底部导航。

**规则：** 不同时出现多个同等强调的大卡片；任务列表使用开放行；摘要使用分隔线；所有入口明确标注目标页面并支持失败/空状态。

### 3.4 Records 记录页

**任务：** 让用户在 10 秒内完成一次体重、饮食、活动或睡眠记录。

**结构：** 页面标题 → 记录类型分段控件 → 单一表单区域 → 保存反馈 → 今日记录时间线。

**规则：** 分段控件只负责切换类型；表单校验贴近字段；保存失败保留输入；修改记录时显示取消修改；底部导航不遮挡保存按钮和时间线。

### 3.5 Xuxu 序序页

**任务：** 提供可持续聊天入口，而不是展示静态介绍。

**结构：** 序序标题区 → 安全边界提示 → 独立消息滚动区 → 快捷问题横向滚动区 → 输入框和发送按钮 → 免责声明。

**规则：** 消息区必须独立滚动；输入区始终可见；快捷问题不挤压输入框；发送按钮在空输入时禁用；序序回答明确是健康管理参考。

**Demo 等价迁移要求：** 序序页以 `prototypes/web-demo/index.html` 的 `#view-chat` 和 `prototypes/web-demo/app.js` 的“咨询”模块为行为基线，先做到结构和交互等价，再增加能力，不重新设计成另一种聊天页。

| Demo 能力 | 小程序实现 | 验收要求 |
| --- | --- | --- |
| `chat-head` | 顶部序序头像、名称、在线状态 | 头像和标题固定，不随消息滚动 |
| `chat-profile` | 健康画像标签区，可收起/展开 | 标签来自已授权档案；未建档显示“尚未建档” |
| `chat-body` | `scroll-view scroll-y` 消息区 | 新消息后滚动到底部；长消息不撑破页面 |
| `chat-welcome` | 空消息欢迎状态 | 初始显示序序头像、主问题和支持范围 |
| `addMsg` | assistant/user 两种气泡 | AI 气泡带序序头像，用户气泡右对齐；知识来源单独成行 |
| `quick-pills` | 横向快捷问题列表 | 点击即发送；至少保留睡眠、外卖、久坐和风险问题四类 |
| `mic-btn` | 语音入口占位 | 当前点击提示“语音输入后续开放”，不伪装成可用语音功能 |
| `chat-input` + `send-btn` | 小程序 input 和发送按钮 | 空内容不可发送，确认键和按钮都能发送，发送后清空并聚焦 |
| `chat-disclaimer` | 底部健康边界说明 | 始终可见，不被 TabBar 或输入区遮挡 |

**入口联动：** 首页序序入口直接打开空聊天；首页快速记录入口打开序序并发送“我想记录一下今天的饮食、睡眠和心情”；知识条目入口打开序序并发送对应问题；任何页面的风险问题都进入同一安全回复流程。

**安全回复：** Demo 中“胸痛”等风险问题不是普通知识回答，必须显示建议及时联系医生或急救服务的安全提示；本阶段不做诊断、不输出药物建议。后续接入 AI 时保留同一消息结构和安全拦截层。

**小程序实现边界：** Demo 使用的 HTML 字符串和内联 SVG 不直接复制到 Vue；文字使用模板渲染，图标使用 `static/icons` SVG，消息列表使用类型化数据，交互语义和视觉层级保持一致。

### 3.6 Plan 计划页

**任务：** 让用户理解当前计划和今天要做的行动。

**结构：** 当前计划摘要 → 今日进度线 → 行动时间线 → 其他可选方向横向列表 → 完成反馈。

**规则：** 不使用两列厚卡片网格；完成状态用统一 `check.svg`；计划调整进入 PlanSetup；无计划时显示单一空状态和主按钮。

### 3.7 PlanSetup 计划设置页

**任务：** 从体重管理或睡眠精力中选择一个当前重点。

**结构：** 应用导航 → 页面标题和一句说明 → 方向选择列表 → 目标字段 → 保存按钮。

**规则：** 方向选择与建档目标语义一致；保存中禁用；API 不可用时使用本地演示计划；返回回到计划页，不回到启动页。

### 3.8 Me 我的页

**任务：** 管理档案、当前计划和数据设置。

**结构：** 页面标题 → 档案摘要行 → 健康管理分组 → 数据与隐私分组 → 免责声明。

**规则：** 不使用右上角装饰叶片；不使用绿色大 Profile 卡；行图标使用正式 SVG；未开放功能必须明确显示“即将开放”且不可误点。

## 4. 导航与状态契约

### 4.1 页面分类

| 分类 | 页面 | 底部导航 | 应用返回 |
| --- | --- | --- | --- |
| 启动 | Bootstrap | 无 | 无 |
| 建档 | Onboarding | 无 | 返回步骤 / 退出建档 |
| 主 Tab | Home、Records、Xuxu、Plan、Me | 有 | 不显示应用返回 |
| 次级页 | PlanSetup | 无 | 返回 Plan |

### 4.2 跳转规则

- Tab 页面只能使用 `uni.switchTab`。
- 非 Tab 页面使用 `uni.navigateTo` 或 `uni.redirectTo`，禁止混用导致返回栈异常。
- 首次建档完成后只能进入 Home；未完成建档时主 Tab 不可访问。
- 保存中、失败、成功、空数据、网络不可用必须有明确 UI 状态。
- 所有按钮必须有真实 `@tap` 行为或明确的“即将开放”提示，不能有无效装饰按钮。

### 4.3 页面状态矩阵

每个页面至少实现以下状态，不能只验证“有数据的正常状态”。

| 页面 | 首次/空状态 | 正常状态 | 保存中 | 失败状态 | 完成状态 |
| --- | --- | --- | --- | --- | --- |
| Bootstrap | 无本地档案 | 有本地档案 | 检测中不显示技术文案 | 检测失败仍可建档 | 重定向 Home |
| Onboarding | 第 0 步 | 第 1-4 步 | 主按钮 loading 且不可重复点 | 本地保存并提示 | 进入 Home |
| Home | 未设置计划 | 今日主行动 | 请求中骨架/短文案 | 显示重新加载但不丢档案 | 今日行动完成反馈 |
| Records | 无记录欢迎条 | 表单与时间线 | 保存按钮 loading | 字段保留输入 | 保存成功 toast/时间线刷新 |
| Xuxu | 欢迎空聊天 | AI/user 消息 | typing 状态 | 安全/服务提示 | 消息可继续追问 |
| Plan | 无计划 | 计划、进度、任务 | 任务按钮禁用 | 本地计划兜底 | 全部任务完成插画 |
| PlanSetup | 默认方向 | 已选方向和字段 | 保存按钮 loading | 保留选择 | 回到 Plan |
| Me | 无计划档案摘要 | 分组设置列表 | 不适用 | 未开放能力提示 | 设置跳转成功 |

### 4.4 逐页视觉验收点

- **Bootstrap：** 主视觉不被系统导航裁切；主按钮位于首屏下半部；无多余返回/退出按钮。
- **Onboarding：** 应用导航与内容之间有明确间距；第 2 步 BMI 数值、标签、建议和刻度同屏；底部操作不覆盖字段。
- **Home：** 第一屏只突出一个主行动；序序入口可见；任务列表和摘要不形成连续厚卡片墙。
- **Records：** 分段控件四项等宽；输入框、单位和错误提示对齐；保存按钮宽度稳定；时间线从表单下方开始。
- **Xuxu：** 消息区高度随屏幕变化；快捷问题不换行撑高；输入框、发送按钮和免责声明完整可见。
- **Plan：** 进度线与任务列表同一主线；方向列表横向滚动但不出现半截关键文字；完成图不抢主标题。
- **PlanSetup：** 方向选择一眼可比较；目标体重字段只在体重方向出现；返回一定回到 Plan。
- **Me：** 档案摘要、分组标题、列表行左边线对齐；没有装饰叶片遮挡标题；不可用功能视觉弱化但文字可读。

### 4.5 入口联动表

| 来源 | 操作 | 目标 | 传递数据 |
| --- | --- | --- | --- |
| Bootstrap | 开始建档 | Onboarding step 0 | 无 |
| Onboarding | 保存并进入首页 | Home | 本地档案/API 档案 |
| Home | 序序入口 | Xuxu | 无 |
| Home | 快速记录 | Xuxu | 预填问题“我想记录一下今天的饮食、睡眠和心情” |
| Home | 今日行动 | Records/PlanSetup | action route |
| Xuxu | 快捷问题/知识入口 | 当前 Xuxu | 文本消息 |
| Records | 修改记录 | Records 顶部表单 | record id + 表单值 |
| Plan | 调整计划 | PlanSetup | 当前 plan kind |
| PlanSetup | 保存计划 | Plan | 本地/API plan |
| Me | 健康档案 | Onboarding | 当前档案 |
| Me | 调整当前计划 | PlanSetup | 当前 plan kind |

## 5. 资源和文件规范

- 唯一图片源：`assets/illustrations/`。
- 小程序同步缓存：`apps/mini/src/static/illustrations/`，由脚本生成，不手工修改。
- SVG 图标目录：`apps/mini/src/static/icons/`。
- 页面只引用 `/static/illustrations/...` 和 `/static/icons/...`，禁止跨目录相对路径。
- `hero.jpg` 仅用于网页端项目展示；小程序建档使用 `onboarding-hero-vertical.png`。新增图片必须先进入 `assets/illustrations/`，再由同步脚本复制到小程序缓存目录。
- 构建产物只保留当前用途：开发时 `dist/dev/mp-weixin`，发布时 `dist/build/mp-weixin`，不同时维护。

## 6. 验收标准

### 视觉

- 八个页面使用同一套背景、文字、边界、圆角和按钮令牌。
- 页面不存在 emoji、Unicode 箭头、微信原生 icon 或 CSS 手绘业务图标。
- 首屏没有标题、图片和操作互相覆盖；小屏和大屏都不出现横向溢出。
- Tab 页面底部内容不被导航遮挡；聊天输入区始终可见。

### 交互

- 建档五步可完成、可返回、可退出、可本地保存并进入首页。
- BMI 输入和滑块实时变化。
- 首页、记录、序序、计划、我的、计划设置之间跳转路径可闭环。
- API 不可用时前端演示流程仍可运行，错误不会把用户卡死在表单页。

### 工程

- 每个页面至少有一条交互测试或组件契约测试。
- 每轮页面改动运行 Vitest、`vue-tsc`、Prettier、微信构建和构建产物检查。
- 微信开发者工具日常只导入 `apps/mini`；发布前才导入 `dist/build/mp-weixin`。

## 7. 分阶段范围

1. **阶段 A：视觉基础与资源治理**：统一令牌、图标、页面壳、TabBar、素材引用和构建目录。
2. **阶段 B：建档与导航闭环**：重做 Bootstrap/Onboarding/PlanSetup，解决截图中的首屏和按钮问题。
3. **阶段 C：首页与序序工作区**：先按 Demo 等价迁移 Xuxu，再重做 Home，验证首屏、入口联动、聊天输入和主行动。
4. **阶段 D：记录与计划闭环**：重做 Records/Plan，验证表单、时间线、任务完成和空状态。
5. **阶段 E：我的页与全量验收**：完成 Me、统一异常状态，运行真机尺寸检查和全量构建。

本设计只规定前端交互和视觉边界，不在本阶段接入真实 AI、食物识别或生产云函数。
