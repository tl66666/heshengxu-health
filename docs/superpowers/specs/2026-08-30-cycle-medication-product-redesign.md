# 生理期与用药产品级改版设计

## 目标

把现有经期、用药入口从“展示型卡片”升级为和生序项目一致的真实健康记录流程，参考薄荷健康的交互节奏，但不复制其品牌视觉。页面必须区分未设置、已设置但暂无记录、已有记录三类状态，禁止内置虚假健康数据。

## 产品边界

- 生理期只做生活记录与周期预测，不做疾病判断、备孕结论或医疗建议。
- 用药只记录用户或医生已经确定的药物信息，不推荐药品、剂量、停药或替代诊疗。
- 第一阶段数据使用现有 UniApp 本地存储接口，字段和 service 边界按后续云端迁移设计。
- 首页只读取真实本地状态；没有数据时显示空状态，不显示示例日期、示例药品或伪造进度。

## 生理期流程

### 首次进入

进入 `/pages/menstruation/MenstruationDetailPage` 时，如果没有周期配置，显示设置态：

1. 月经周期天数：默认输入框为空，允许 20-45 天。
2. 经期天数：默认输入框为空，允许 2-10 天。
3. 最近一次经期开始日期：使用日期选择器，不预填日期。
4. 可选项：最近一次经期结束日期；不填写时按经期天数估算。
5. 保存后才创建周期配置并进入周期主页。

### 周期主页

设置完成后展示：

- 当前周期第几天、距离下次预计开始天数、预计日期。
- 月历作为主视觉：真实经期使用樱花粉，预测经期使用淡紫，今天使用细描边。
- 点击日期进入该日记录；支持补记、修改和取消经期标记。
- 症状记录包括疼痛程度、乏力、腰酸、腹胀、头痛、情绪波动、食欲变化和自由备注。
- “周期设置”入口允许修改周期长度、经期长度、最近一次经期日期，并重新计算预测。
- 页面底部保留简短免责声明，不制造恐慌。

## 用药流程

### 空状态

没有药物时显示安静的空状态和“添加第一条提醒”操作，不展示示例药名或虚假完成比例。

### 用药主页

- 顶部显示今日已完成数量 / 总提醒数量；无药物时不显示百分比环。
- 提醒按时间排序，每条展示药物名称、用户填写的剂量说明、频次和时间。
- 点击圆形勾选完成今日打卡；打卡记录按日期保存，第二天自动恢复待完成。
- 删除通过确认弹窗完成；不隐式删除历史数据。
- 添加表单字段：药物 / 提醒名称、剂量说明、频次（每日 / 每周 / 按需）、提醒时间、备注。
- 表单保存前必须填写名称；剂量默认显示“按医嘱”作为占位语义，不作为医疗建议。
- 页面底部显示用药安全提示，明确以处方、说明书和医生指导为准。

## 首页联动

- 经期卡片：无配置显示“先设置周期”；有配置显示当前周期状态和预计日期。
- 用药卡片：无提醒显示“添加一条提醒”；有提醒显示今日完成数量。
- 首页入口支持整卡和加号进入对应页面；返回首页后重新读取本地状态。

## 视觉规则

- 延续现有治愈系日系清新水彩风格：浅薄荷背景、留白、细边框、低对比阴影、圆角不超过现有系统规范。
- 生理期使用柔和樱花粉 / 淡紫，避免荧光粉和大面积高饱和渐变。
- 用药使用雾蓝 / 薄荷绿，和经期页面形成语义区分，但共享字体、间距、导航和按钮系统。
- 使用现有水彩插画资源；药品图标仅作为弱化辅助视觉，不把插画当作真实药品图片。
- 页面首屏优先展示状态和下一步操作，不堆叠装饰卡片。

## 验证

- 首次进入经期页：无日期和预测数字，完成设置后才出现预测。
- 修改周期参数后，月历和预测日期同步变化。
- 用药添加、编辑 / 删除、打卡和跨日重置均可在本地复现。
- 首页摘要与详情页数据一致。
- 对新增 Vue 页面进行 SFC 脚本 / 模板编译检查，并运行现有测试集，区分既有失败与本次回归。
