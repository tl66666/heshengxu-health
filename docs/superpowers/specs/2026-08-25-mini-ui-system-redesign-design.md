# 和生序小程序 UI 系统重构设计

## 目标

解决当前微信小程序页面中旧 Demo 残留、字符图标、布局层级不一致、返回路径不明确和序序入口不稳定的问题。重构后用户应能在 3 秒内看懂当前页面、下一步动作和返回方式；首页、记录、计划、序序、我的五个主页面保持同一套视觉语言。

## 视觉方向

- 气质：治愈、克制、轻量，使用二次元序序插画作为陪伴信号，不使用真人图片。
- 背景：`#F6FAF7`；内容卡片：`#FFFFFF`；序序提示：`#FFFBEA`。
- 主色：`#2E7D4F`；浅绿：`#EAF5EB`；主要文字：`#244735`；辅助文字：`#70897A`；错误：`#B85E43`。
- 页面左右边距 32rpx；常规卡片圆角 16rpx；Hero 圆角 22rpx；主按钮高度 84rpx；底部导航上方预留至少 190rpx。
- 标题使用 34~44rpx，正文 24~28rpx，辅助说明 20~22rpx，行高 1.5~1.65。
- 不允许使用 Unicode 字符、emoji、CSS 手绘图形或临时手写图标。业务导航使用 `static/icons` 中的标准线性 SVG 资源；系统返回/状态图标才使用微信原生 `<icon>`，插画只使用 `static/illustrations` 中的位图资源。

## 页面结构

### 首页

顶部显示问候、日期和序序头像；Hero 只保留一个主 CTA；其下为序序快捷聊天入口、今日小行动、今日记录摘要和当前计划摘要。每个摘要都是整行可点击区域，右侧使用原生 `forward` 图标。首页只承担“今天做什么”的决策，不堆叠数据图表。

### 记录

顶部标题与一句解释；四类记录使用可横向滚动的分段按钮；场景提醒紧邻表单；表单卡片只展示当前类型需要的字段；保存后展示今日时间线。类型切换和选中状态必须有明确颜色和边框差异，勾选状态使用 `success_no_circle`。

### 计划

无计划时展示单一空状态和设置按钮；有计划时展示 Hero、方案网格、今日行动列表和完成提示。完成按钮使用原生成功图标，不显示字符勾号；不可用方案降低透明度并给出“后续开放”文字。

### 序序

顶部标题固定；聊天区占据主要空间，消息列表在中间独立滚动，快捷问题为横向胶囊，输入框和免责声明固定在聊天区底部，首次打开无需额外下滑即可开始提问；保留医疗安全提示。底部导航中央序序头像作为主入口，首页也保留一张明确的“和序序聊聊”卡片，形成场景化入口。

### 我的

顶部标题、序序头像和档案摘要；按“健康管理”“数据与隐私”分组；每一行使用原生 `info_circle` 和 `forward` 图标，暂未开放能力用文字说明，不使用伪按钮。

### 建档

建档期间隐藏底部导航，普通页面不能被点击；顶部使用统一 `AppNavBar`，左侧返回、右侧退出。四步进度固定在标题下方；身高/体重输入与滑块双向同步，BMI 和“偏瘦/正常/偏重/肥胖”实时更新；完成保存后才解锁主导航。

## 组件和导航规范

- `AppNavBar`：所有非 Tab 页面必须使用，按钮触控面积不少于 88rpx。
- `MiniTabBar`：固定五栏，中央序序突出显示；页面内容底部统一预留空间。
- `XuxuHint`：场景化提示卡，右侧动作使用原生 `forward`。
- 页面内操作按钮：主操作使用实心绿色，次操作使用浅绿底，危险/退出使用浅红底；所有按钮文字必须完整可读。
- Tab 页面之间只使用 `switchTab`；详情和设置页使用 `navigateTo`；返回优先 `navigateBack`，无历史时回到对应 Tab。

## 验收标准

1. `rg` 检查源码不再出现 `›`、`鈥`、`⌂`、`◷`、`◌`、`☾` 等字符图标。
2. 微信构建成功，产物包含首页聊天入口、`AppNavBar`、`XuxuChatComposer` 和五栏导航。
3. 每个主页面都能从底部导航进入，详情页都有返回或退出按钮。
4. 建档未完成时首页、记录、计划、序序、我的均不可点击，完成后才解锁。
5. Vitest、`vue-tsc`、Prettier、微信构建和产物检查全部通过。
