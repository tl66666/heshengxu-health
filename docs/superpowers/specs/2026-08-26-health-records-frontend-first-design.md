# 健康记录模块（前端优先）设计

## 目标

让已完成建档的用户可以在微信小程序中稳定完成一次体重、饮食、活动或睡眠记录，并立即在记录页和首页摘要看到结果。前端先形成可操作的完整体验，后端只在接口边界和数据一致性上配合验证。

## 用户流程

1. 用户进入“记录” Tab，看到四类记录切换和今日记录时间线。
2. 选择一种记录类型，表单只展示该类型需要的字段。
3. 点击保存后显示保存中状态；成功后清空当前表单、刷新今日时间线并提示“已保存”。
4. 点击时间线中的“修改”，表单回填对应数据；保存后以版本化修改替换旧记录。
5. 网络失败时保留用户输入，显示明确错误和“重试保存”，不伪造成功状态。

## 前端边界

新增 `apps/mini/src/features/health-records/`：

- `health-records.types.ts`：表单状态、时间线展示模型和校验错误类型。
- `health-records.validation.ts`：不依赖 Vue/uni 的字段校验纯函数。
- `health-records.mapper.ts`：API DTO 到时间线/表单模型的转换。
- `health-records.service.ts`：记录 API 的请求编排，复用现有 API transport。
- `health-records.store.ts`：当前日期、记录列表、保存中/错误/编辑状态。

`RecordsPage.vue` 只负责布局和事件绑定；不再直接拼装 API payload 或重复校验规则。现有 `health-loop` 聚合服务继续负责首页所需的 `DailyHomeDto`，记录域不反向依赖页面。

## 交互和视觉

- 页面使用一个主表单区域和一个时间线区域，不嵌套多层卡片。
- 类型切换使用轻量分段控件，不显示手写图标或 emoji。
- 主按钮固定为“保存记录”或“保存修改”，保存中显示 loading 并禁用重复提交。
- 所有错误显示在对应表单下方；网络错误保留输入内容。
- 空状态使用现有 `record-desk-banner.png`，只出现一次。
- 底部导航继续使用 `MiniTabBar`，页面底部预留空间。

## 后端配合

前端闭环完成后补充：

- DTO 的日期、数值范围和字符串长度测试。
- 当前用户隔离测试。
- 修改接口的 `isCurrent/previousRecordId/supersededAt` 版本链测试。
- 今日查询只返回 `isCurrent=true` 且处于上海时区日期范围内的数据。

## 不做事项

本阶段不实现热量估算、食物拍照识别、真实 AI 回复、趋势图和健康评分；这些功能依赖稳定的记录数据，将在后续阶段单独设计。

## 验收标准

- 四类记录均可完成“选择 -> 填写 -> 保存 -> 时间线展示”。
- 修改记录不会覆盖历史版本，页面只展示当前版本。
- 空状态、保存中、校验失败、网络失败均有可见状态。
- 前端单测覆盖四类校验和 DTO 映射；后端测试覆盖接口隔离和版本链。
- `vue-tsc`、Vitest、微信构建和构建产物检查全部通过。
