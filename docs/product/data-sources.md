# 数据来源与复用边界

## 当前结论

仓库只把公开项目作为结构和交互参考，不直接复制没有明确许可证的代码、图片或数据库内容。此前审阅的参考项目包括：

- `chenyy0708/BooheeFlutter`：参考首页工具入口、底部导航和数据卡片层级
- `xiaok0928/spider-boohee-data`：参考食物、分类和运动数据的字段形态
- `KoWhite/food-crawler`、`orcatt/BoHeSpider`：参考食物详情、营养、别名和计量单位的采集字段

审阅后发现：`BoHeSpider` README 明确限定学习和研究用途；`spider-boohee-data` 仅声明爬取来源且未提供数据许可证；其余仓库也没有提供可直接复用食物数据的明确授权。因此不把其实现、图片或原始数据提交到和生序产品。

本地审阅副本位于工作区外的 `D:\禾伴\references\`，不属于产品仓库，也不会提交。

## 后续食物数据模块

正式接入前需要完成：

1. 确认数据授权或改用有明确许可的公开数据集。
2. 在 `packages/contracts` 定义食物、营养素、别名和计量单位契约。
3. 在 API 侧增加只读食物目录模块，记录来源、抓取时间和版本。
4. 食物图片使用可追溯来源或重新生成的原创插画，不直接引用第三方站点图片。
5. AI 拍照识别只返回候选食物和待确认结果，不能把识别结果直接当作真实摄入或医疗建议。

在上述条件满足前，小程序不展示虚假的食物热量、营养或拍照识别结果。

## 本地 SQL 文件的处理

仓库根目录曾出现 `food.sql` 与 `food_category.sql` 两个结构化表文件。它们只用于审查字段设计和导入映射，不属于产品运行时数据，也不会提交到 Git 或打包到小程序。正式导入必须由数据负责人提供可核验的授权声明；导入服务会强制要求 `sourceName` 与 `sourceLicense`，缺失时直接拒绝。

从这两个表中吸收的字段包括：食品分类、食品名称/搜索别名、每 100g 热量与三大营养素、膳食纤维、钠，以及可选的维生素和矿物质扩展字段。当前 Prisma 核心模型先保存产品实际使用的核心营养字段，扩展字段待授权数据源确定后再追加，避免无来源数据进入用户历史记录。
