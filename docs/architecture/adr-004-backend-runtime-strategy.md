# ADR-004：本地后端与微信云开发的边界

状态：已接受
日期：2026-08-26

## 决策

当前开发阶段采用 NestJS 模块化 API + Prisma/PostgreSQL 作为唯一事实后端，Redis 只作为本地缓存和异步任务基础设施。微信云开发不参与本地数据写入，也不与 NestJS API 并行承载同一套业务接口。

## 为什么这样做

- 当前项目已有 NestJS 模块、Prisma schema、migration、OpenAPI 和服务端测试。
- 小程序前端可以完全脱离后端做页面和交互开发，因此不需要为了看页面启动 Docker。
- 两套后端同时写数据会产生认证、数据一致性、迁移和排错成本，当前阶段没有必要。
- 后续需要云端部署时，可以把对象存储和视觉 Provider 替换为 CloudBase 适配器；上层页面和业务契约保持不变。

## 使用方式

| 场景 | 需要 Docker | 需要微信云开发 |
| --- | --- | --- |
| 只看/调试 uni-app 页面 | 否 | 否 |
| 联调健康档案、食品目录、餐食记录 API | 是 | 否 |
| 本地执行 Prisma migration/seed | 是 | 否 |
| 未来线上小程序云端运行 | 否（本机） | 是，按部署方案选择 |
| 混元视觉和图片对象存储生产接入 | 否（本机） | 推荐使用云端适配器 |

## 迁移原则

在正式切换 CloudBase 前，先完成认证、数据库迁移、对象存储、Provider、日志审计和回滚方案评估。切换时只替换基础设施适配器，不在页面内直连云端 SDK 或写入密钥。
