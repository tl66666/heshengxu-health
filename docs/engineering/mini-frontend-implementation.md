# 小程序前端实施规范

**适用范围：** `apps/mini` 微信小程序前端

## 1. 本轮目标

本轮以 `prototypes/web-demo` 的已确认体验为视觉参考，把 Demo 中值得保留的欢迎叙事、序序陪伴、今日唯一行动和轻量记录迁移到正式 uni-app 页面。正式页面必须使用真实档案、计划和记录状态；Demo 中的健康分、虚构热量、趋势线和自由聊天不作为实现依据。

## 2. 页面职责

| 页面 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| `bootstrap` | 启动过渡与品牌识别 | 不承载业务数据 |
| `onboarding` | 四步建档、身高体重输入、实时 BMI、目标选择 | 不提前展示首页导航 |
| `home` | 今日唯一主行动、最多三件真实待办、记录摘要 | 不生成虚构趋势或健康分 |
| `records` | 体重、饮食结构、活动、睡眠的轻量记录 | 不做医疗诊断或自动估算热量 |
| `plan` | 健康主题入口、今日行动、完成反馈 | 未开放主题必须明确标记为后续开放 |
| `xuxu` | 规则化的记录解释、快捷问题和安全支持 | 不提供无边界自由聊天 |
| `me` | 当前档案、已选计划和设置入口 | 未实现能力不能显示为可用 |

建档未完成时，底部导航只显示不可用状态；只有档案保存成功后才解锁首页、记录、计划、序序和我的页面。

## 3. 视觉和组件规则

- 基调：清新水彩、嫩绿和暖黄色，动漫治愈感来自插画，不用真人图片。
- 数据页面优先信息层级和留白；插画只承担欢迎、空状态、完成和场景提醒，不覆盖表单或关键数据。
- 所有按钮、输入框和图片在 `App.vue` 做基础 reset，避免微信原生默认边框、内边距和图片基线造成错位。
- 重复的按钮、空状态、Hero 和底部导航必须使用已有组件或统一 token，不在页面内复制一套样式。
- `序序`同时存在于底部中央常驻入口和具体场景提醒中；场景提醒只解释当前页面事实，不替代页面操作。
- BMI 使用同一套 BMI 规则和颜色分段，身高、体重滑杆与输入框双向同步，数值变化时即时显示偏瘦、正常、偏重或肥胖。

## 4. 图片资产规则

唯一源目录是 `assets/illustrations/`。页面通过 `@/static/illustrations/<file>` 使用，开发和构建脚本会自动同步到 `apps/mini/src/static/illustrations/`；后者是构建缓存，不手工维护，也不提交 Git。

图片用途必须记录在 `assets/README.md`：欢迎图只用于启动或建档，主题图只用于对应计划，序序图只用于陪伴和安全提示。新增图片前先确定页面尺寸、裁切方式、失败状态和文案，再调用 GPT Image 2，并把提示词和来源补入素材清单。

## 5. 数据和参考仓库边界

外部产品和 GitHub 仓库不属于和生序的运行时依赖。没有明确商用许可证的代码、图片和原始数据库不得复制进项目。后续食物数据必须先确认授权，再由服务端导入并保留来源、版本、单位和别名字段；小程序页面不得直接读取爬虫数据或数据库。

页面只消费 `services` 和 `stores` 输出的前端模型。BMI、完成状态和记录摘要等规则放在 `packages/domain` 或 `features`，不能在模板中散落计算。

## 6. 微信开发和验收

日常开发在仓库根目录运行：

```powershell
./scripts/dev-mini.ps1
```

微信开发者工具导入 `apps/mini`，不要导入 `apps/mini/src` 或旧的 Demo。保存源码后在微信工具点击“重新编译”即可；发布预览运行 `./scripts/build-mini.ps1`，导入 `apps/mini/dist/build/mp-weixin`。

每次前端改动至少执行：

```powershell
npm exec -- vitest run
npm exec -- vue-tsc --noEmit --pretty false
npm exec -- uni build -p mp-weixin
node scripts/verify-mini-build.mjs
```

人工验收顺序：首次打开只能建档；BMI 随输入实时变化；保存后底部导航解锁；首页、记录、计划、序序和我的页面图片无空白、无裁切错位、无默认按钮留白；窄屏文字不溢出，底部导航不遮挡内容。
