## 下一轮实施顺序

1. 完成食品识别领域契约和 Mock Provider，先验证“候选而非结论”的边界。
2. 增加识别任务与候选表、查询接口和确认接口；确认前不得创建 MealEntry。
3. 在小程序加入拍照入口、处理中状态、候选编辑和确认页面。

5. 最后接 CloudBase 与混元视觉；Provider Key 只放服务端环境变量。

## 质量门禁

- 领域计算必须有先失败后通过的 Vitest 测试。
- API 必须通过 `tsc -p apps/api/tsconfig.build.json --noEmit`。
- 小程序必须通过食品/导航测试和 `npm exec -- uni build -p mp-weixin`。
- 每个真实识别结果必须显示为候选，用户确认后才写入餐食记录。
